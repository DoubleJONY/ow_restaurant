## ORG 매핑

기존 아이템 수는 475개이며 냉각총 하나를 추가해 최종 476개, 코드 범위 `0..475`가 된다.

공통 장비는 다음 쌍 교환을 적용한다.

```text
1<->61, 2<->62, 3<->63, 4<->64, 5<->65, 6<->265,
7<->354, 8<->352, 9<->353, 10<->355, 11<->356,
12<->357, 13<->358, 14<->359, 15<->360, 16<->361,
17<->434, 18<->432
```

보존식 박스와 냉각총 슬롯은 다음과 같이 만든다.

```text
old 433 보존식 박스 -> new 19
old 19 음식       -> new 433
new 냉각총         -> new 20
old 20 음식       -> new 475
```

그 밖의 기존 코드는 identity mapping이다.

## CAFE 매핑

기존 아이템 수는 398개이며 보존식 박스 하나를 추가해 최종 399개, 코드 범위 `0..398`이 된다.

기존 공통 장비 `0..18`은 이미 표준과 동일하다.

```text
new 보존식 박스    -> new 19
old 19 음식       -> new 398
old 351 냉각총    -> new 20
old 20 음식       -> new 351
```

그 밖의 기존 코드는 identity mapping이다.

## GC 매핑

기존 아이템 수는 462개이며 두 도구를 추가해 최종 464개, 코드 범위 `0..463`이 된다.

기존 공통 장비 `0..18`은 이미 표준과 동일하다.

```text
new 보존식 박스 -> new 19
new 냉각총      -> new 20
old 19 음식    -> new 462
old 20 음식    -> new 463
```

그 밖의 기존 코드는 identity mapping이다.

## 공통 장비 목록과 ordinal

```ow
Global.KNIFE = Array(1, 6, 2, 3, 4, 5, 7);
Global.PERK_LIST = Array(
    Array(8, 9, 11, 12, 15, 16, 17, 19, 20),
    Array(10, 13, 14)
);
```

| `itemPerk` | 아이템 | 활성 에디션 |
|---:|---|---|
| 0 | 에너지 드링크 | 전체 |
| 1 | 수상한 드링크 | 전체 |
| 2 | 조미료 팩 | 전체 |
| 3 | 청소기 | 전체 |
| 4 | 요리 복사 스펠 | 전체 |
| 5 | 토치 | 전체 |
| 6 | 서빙볼 | 전체 |
| 7 | 보존식 박스 | ORG |
| 8 | 냉각총 | CAFE |

전체 `PERK_LIST`는 장비 판별과 ordinal 고정에 사용한다. 랜덤 드랍은 별도 활성 목록을 사용한다.

```text
ORG  item perk drop: 8, 9, 11, 12, 15, 16, 17, 19
CAFE item perk drop: 8, 9, 11, 12, 15, 16, 17, 20
GC   item perk drop: 8, 9, 11, 12, 15, 16, 17
공통 foot perk drop: 10, 13, 14
```

## 변환 불변조건

- 기존 아이템 매핑은 파일별로 injective여야 한다.
- 새로 추가되는 도구 슬롯과 기존 아이템의 목적 슬롯이 충돌하면 안 된다.
- 아이템 코드 `0`은 고정한다.
- `False`, `True`, `Null`, `-1`, `-2`를 아이템 코드로 일괄 변환하지 않는다.
- `STAGE_CODE`는 메뉴 그룹 인덱스이므로 변환하지 않는다.
- `UPGRADE_CODE`에서는 실제 아이템인 `[0][0]`만 변환한다.
- 기존 아이템의 모든 데이터 레코드는 새 코드에서 의미가 동일해야 한다.

## RAW 레시피 변환

각 에디션의 원본 행 순서를 유지하며 다음을 적용한다.

```text
oldLeft   = floor(RAW_MIX[i] / 1000)
oldRight  = RAW_MIX[i] % 1000
newMix    = M(oldLeft) * 1000 + M(oldRight)
newResult = M(RAW_RESULT[i])
```

- ORG: 306행
- CAFE: 255행
- GC: 282행

`RAW_RESULT`는 per-item 배열이 아니므로 슬롯 순열을 적용하지 않는다. 같은 행의 결과 코드 값만 변환한다. 행 순서, 좌우 방향, self-pair, 중복을 보존한다.
