## 편집과 검사

**실행 코드와 모든 게임 데이터의 원본은 루트의 `.ow` 파일입니다.** 메뉴·레시피·아이템·번역도 해당 파일에서 직접 수정합니다. 빌더 실행, 번역표 역동기화, 생성 결과 일치 검사는 더 이상 필요하지 않습니다.

```powershell
python -B scripts/check_ow_syntax.py "*.ow"
python -B -m unittest discover -s tests -v
git diff --check
```

Python 3.10 이상을 사용합니다. 파일 하나만 검사하려면 `"*.ow"` 대신 파일 경로를 지정합니다. 새 루트 `.ow`는 목록 수정 없이 자동 검사됩니다. GitHub Actions의 **OW syntax** 잡도 같은 방식으로 검사합니다. 검사기는 입력 파일을 변경하지 않습니다.

- 현재 원본: `kr_deluxe.ow`, `en_deluxe.ow`, `jp_deluxe.ow`, `kc_kr.ow`, `n3_kr.ow`
- [참고 자료](reference/README.md): 과거 번역표·아이템 매핑·검증 보고서·아이템 이름 Excel. 현재 원본과 다르면 `.ow`를 따릅니다.
- `deprecated/`: 이전 버전 비교용. 현재 원본을 생성하는 입력이 아닙니다.
- `.codex/artifact/`: 과거 작업 기록. 기록 속 빌더 실행·역동기화 절차는 폐기되었습니다.

빌더와 중복 생성 파일은 제거했습니다. 이전 구현은 Git 이력에서 조회할 수 있습니다. 참고 자료는 자동 적용하거나 최신 데이터로 간주하지 않습니다.

[문법 검사 범위와 사용법](scripts/OW_SYNTAX.md)을 참고하세요. 문법 검사는 함수·인자 타입이나 게임 동작을 보장하지 않으므로, 데이터와 동작 변경 시 아래의 의미 검증 및 필요한 게임 내 검증을 별도로 수행합니다.

## 언어별 스테이지·튜토리얼 검증 필수

**KR·EN·JP는 같은 모드·스테이지라도 메뉴 순서와 등장 테마가 다를 수 있습니다.** 다른 언어의 튜토리얼을 번역하거나 공통 코드를 복사하는 것만으로 동작이 보장되지 않습니다.

- 튜토리얼, 스테이지 순서, 메뉴·레시피·재료 공급을 변경하면, 영향을 받는 각 언어의 실제 `.ow`에서 반드시 검사합니다.
- `stageMode` → `STAGE_CODE[Global.stage]` → `MENU_LIST`·`FRIDGE_LIST`·추가 재료 공급을 추적하고, `setHint` 실행 후의 실제 주문 목록(`currentMenu`·`loadingMenu`)과 조리 안내(`hintText`)를 비교합니다. 안내와 주문이 등장 테마에 맞고, 제공 재료와 레시피로 실제 조리 가능한지 확인해야 합니다.
- 튜토리얼 켜짐·꺼짐과 해당되는 연습 모드 진입 경로도 검사합니다. 문법 검사 통과만으로 튜토리얼과 실제 게임 데이터의 일치를 보장하지 않습니다.
- 화면의 스테이지 번호와 코드의 0 기반 인덱스를 구분하고, 검사 결과에 언어별 의도적 차이·튜토리얼 생략 여부와 게임 내 실행 검증 여부를 기록합니다.

### 회귀 방지 사례: 일본어판 캐주얼 다이닝 stage 8

2026-09-19 확인 기준, 일본어판 클래식 캐주얼 다이닝의 인덱스 7·10·13은 만두 테마 대신 생선 계열 테마를 사용합니다. 화면의 **stage 8은 `Global.stage == 7`**입니다. 이 위치에 만두 튜토리얼이 남아 생선 주문을 만두 주문으로 덮어쓰면서 진행 불가 문제가 발생했습니다. 현재는 사용자 요청에 따라 생선구이 → 주먹밥 → 초밥 → 찐 어묵 → 튀긴 어묵 → 흰살생선튀김 → 돈가스 → 돈가스+밥 → 가츠동 → 가라아게동 → 오야코동의 일본어 전용 튜토리얼로 교체했습니다. 첫 주문 사이클만 이 11종을 사용하고, 이후에는 기존 전체 정규 메뉴 13종으로 돌아갑니다. 다른 언어와 동기화할 때 만두 튜토리얼을 되살리거나 정규 메뉴 전체를 11종으로 제한하지 않아야 합니다. 메뉴 배치는 이후 변경될 수 있으므로 항상 최신 테이블을 확인합니다.
